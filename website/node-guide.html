Run a public mainnet node

Help other Obsolete Coin nodes find peers, verify blocks and catch up. You can run a node without a wallet or a miner.

Windows · Linux · Router setup · Check your node

1. Prepare the mainnet settings

Use a computer that can stay awake and online, with disk space for the growing blockchain. The desktop wallet opens outbound connections. To accept other nodes, run the bitcoind program included in the same Obsolete Coin download. The steps below give it a separate data folder.

Open the current mainnet peer and copy the full address shown after “Current peer”, including :19777. In the configuration below, replace CURRENT_PEER with that address. Save the file in the Windows or Linux step below.

[obsolete]
listen=1
bind=0.0.0.0:19777
onlynet=ipv4
listenonion=0
server=1
disablewallet=1
rpcbind=127.0.0.1
rpcallowip=127.0.0.1
rpcport=29779
addnode=CURRENT_PEER

Peers use TCP 19777. The local administration commands below use TCP 29779 so that the desktop wallet can keep its default RPC port, 9778. Keep both RPC ports local.

2A. Windows x64

  1. Download the Windows portable ZIP from Downloads. In PowerShell, run Get-FileHash -Algorithm SHA256 .\FILE.zip in the download folder, substituting the ZIP filename. Compare the full hash with the one on the download page. Extract the whole ZIP to a permanent location and open PowerShell in the folder containing bitcoind.exe and its DLLs.
  2. Create the node folder and open its configuration file: 
    $nodeDir = Join-Path $env:LOCALAPPDATA 'ObsoleteCoin-PublicNode'
New-Item -ItemType Directory -Force -Path $nodeDir | Out-Null
notepad.exe (Join-Path $nodeDir 'obsolete.conf')
    Paste the settings from step 1. Save as obsolete.conf using “All files” if prompted. Check that the name does not end in .txt.
  3. On your trusted home network, use Get-NetConnectionProfile to check that the connection profile is Private. Open a separate PowerShell window as administrator in the same executable folder and add this Windows Firewall rule once: 
    New-NetFirewallRule -DisplayName "Obsolete Coin mainnet P2P" -Direction Inbound -Action Allow -Profile Private -Protocol TCP -LocalPort 19777 -Program (Resolve-Path .\bitcoind.exe).Path
  4. Start the node in the original, non-administrator PowerShell window and leave it open: 
    .\bitcoind.exe -chain=obsolete "-datadir=$nodeDir"
    In a second PowerShell window in the executable folder, define this shortcut for step 4: 
    function nodecli { & .\bitcoin-cli.exe -chain=obsolete "-datadir=$env:LOCALAPPDATA\ObsoleteCoin-PublicNode" @args }
Start automatically when you sign in

Stop the manually started node with nodecli stop. In Task Scheduler create a task for your Windows account with an “At log on” trigger. For “Start a program”, browse to the extracted bitcoind.exe. Set the arguments to -chain=obsolete -datadir="FULL_DATA_FOLDER", replacing FULL_DATA_FOLDER with the path printed by Write-Output $nodeDir in the original window. Run the task and check it with nodecli getnetworkinfo.

2B. Linux (Debian 13 x86-64)

  1. Download the Linux x86-64 archive from Downloads. From the directory containing the archive, run the commands below. Compare the checksum with the download page before extracting. 
    sha256sum @LINUX_ARCHIVE@
sudo apt-get update
sudo apt-get install nano libevent-core-2.1-7t64 libevent-extra-2.1-7t64 libevent-pthreads-2.1-7t64 libsqlite3-0 libstdc++6 libgcc-s1
mkdir -p "$HOME/obsolete-node-app"
tar -xzf @LINUX_ARCHIVE@ -C "$HOME/obsolete-node-app"
cd "$HOME/obsolete-node-app/obsoletecoin-linux"
  2. Create a private data folder and edit the configuration as your normal user: 
    install -d -m 700 "$HOME/.obsoletecoin-public-node"
nano "$HOME/.obsoletecoin-public-node/obsolete.conf"
    Paste the settings from step 1. Press Ctrl+O, Enter, then Ctrl+X. If your machine uses an active UFW firewall, allow incoming P2P with sudo ufw allow 19777/tcp. With another firewall, add the equivalent inbound TCP rule. Debian firewall reference.
  3. Start the node and define the command shortcut for step 4 in the same shell: 
    ./bitcoind -chain=obsolete -datadir="$HOME/.obsoletecoin-public-node" -daemonwait
nodecli() { "$HOME/obsolete-node-app/obsoletecoin-linux/bitcoin-cli" -chain=obsolete -datadir="$HOME/.obsoletecoin-public-node" "$@"; }
Start automatically at boot with systemd

Stop the manual instance with nodecli stop and wait for it to exit. Create ~/.config/systemd/user/ with mkdir -p ~/.config/systemd/user. Save the following as ~/.config/systemd/user/obsolete-public-node.service.

[Unit]
Description=Obsolete Coin public mainnet node

[Service]
ExecStart=%h/obsolete-node-app/obsoletecoin-linux/bitcoind -chain=obsolete -datadir=%h/.obsoletecoin-public-node
Restart=on-failure
RestartSec=10
TimeoutStopSec=180

[Install]
WantedBy=default.target
systemctl --user daemon-reload
systemctl --user enable --now obsolete-public-node.service
sudo loginctl enable-linger "$(id -un)"
systemctl --user status obsolete-public-node.service

Lingering lets the user service start at boot and continue after logout. Stop it with systemctl --user stop obsolete-public-node.service.

3. Forward the public port

  1. Find the node computer’s LAN IPv4 address using ipconfig on Windows or ip -4 addr on Linux. Reserve that address for the computer in your router’s DHCP settings.
  2. In the router’s “Port forwarding”, “NAT” or “Virtual server” menu, forward external TCP 19777 to TCP 19777 at the reserved LAN address. Leave RPC out of the rule. On a VPS with a public IPv4 address, allow TCP 19777 in the provider firewall as well as the host firewall.
  3. If two routers perform NAT, forward through both. If your ISP uses carrier-grade NAT (CGNAT), ask for a public IPv4 address or use a host with one. Your node can still make outbound connections while you arrange inbound access.

4. Verify synchronization and inbound connections

Use the nodecli shortcut from your platform section. In a new shell, define the shortcut again.

nodecli getblockhash 0
nodecli getblockchaininfo
nodecli getnetworkinfo
  1. The block-zero hash must match the Obsolete Coin mainnet genesis: @GENESIS@.
  2. In getblockchaininfo, check that chain is obsolete. Once synchronized, initialblockdownload is false and blocks matches headers. Compare your height and best block hash with the live explorer.
  3. Test from a different internet connection. Ask someone running a mainnet wallet to open Network → Connect peer and enter YOUR_PUBLIC_IPV4:19777. While connected, run nodecli getpeerinfo on your node and look for their connection with "inbound": true. A nonzero connections_in in getnetworkinfo also confirms an incoming peer.
My node has no peers, or only outbound peers

If there are zero peers, compare addnode in your config with the current peer. If the address has changed, update the file and restart the node. If outbound connections work but the external test fails, check that the node is listening with Get-NetTCPConnection -LocalPort 19777 -State Listen on Windows or ss -ltn 'sport = :19777' on Linux. Then check the firewall profile, router forwarding target and ISP connection. A successful test from the same Wi-Fi only confirms local access.

To shut down a manually started node, run nodecli stop and let it finish writing the chain data. For service-managed nodes, stop the task or service after a clean shutdown. If your public IP changes, give peers the new address.
